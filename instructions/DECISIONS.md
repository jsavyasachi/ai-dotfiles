# Decisions

Durable decision log for `ai-dotfiles`. One line per decision, newest last. Split out of
`instructions/AI.md` on 2026-08-03 so the
log stops loading into every agent session.

- 2026-05-04: commit/push cadence uses hybrid architecture: prose policy in `AI.md` + `/commit` and `/push` slash commands + soft Stop hook (dirty-tree nag on session end)
- 2026-05-04: "logical stage" = a TodoWrite task reaching `completed` - one task, one Conventional Commit; don't accumulate uncommitted work across tasks
- 2026-05-04: `/push` = `git push` current branch as-is; no PR auto-creation, no main-branch gating; relies on existing docs-audit rule
- 2026-05-04: OpenCode gets policy + commands but no Stop hook in v1 - hook system is plugin-based (`hooks.yaml`), deferred
- 2026-05-04: Gemini Stop hook deferred if v0.26+ syntax is unstable; policy + commands land regardless
- 2026-05-04: cross-agent commit cadence commands are `/commit` and `/push`; no legacy aliases
- 2026-05-31: SKILL.md/command `description:` must be single-quoted; enforced by `extensions/hooks/validate-skill-frontmatter.sh` via a git pre-commit hook (cross-agent: fires for any agent that commits) + a `setup.sh` self-check and re-quoting generator. Codex's strict YAML rejects unquoted `: `/` #`; Claude's lenient parser hides it
- 2026-07-08: clarifying-question policy is agent-conditional - Claude Code uses `AskUserQuestion`, Gemini CLI uses `ask_user`, OpenCode uses `question`, Codex's `request_user_input` is Plan-Mode-only, Cursor has no confirmed structured tool so it asks in plain text with enumerated options
- 2026-07-11: Gemini CLI hooks are documented and stable enough to configure through `settings.json`; the earlier v0.26+ deferral is resolved, though this repo does not yet install Gemini hooks
- 2026-07-16: Ghostty and tmux settings are tracked as repo templates and merged by `setup.sh` into labeled managed blocks, preserving user-owned settings outside those blocks
  - **Superseded 2026-07-23** for tmux: only Ghostty is managed now (see 2026-07-23 entry)
- 2026-07-19: The local-model stack is Ollama plus `qwen2.5-coder:14b`, chosen for 16 GB Apple-silicon machines; `config/local-models.txt` declares the model, `setup.sh` installs and pulls it idempotently, and `OLLAMA_CONTEXT_LENGTH=16384` is required because the `/v1` endpoint cannot raise context per request
- 2026-07-19: OpenCode defaults to `ollama/qwen2.5-coder:14b` via `config/opencode.json.tpl`; override per run with `opencode run -m provider/model`
- 2026-07-19: The `opencode` cross-agent skill mirrors the `codex` delegation skill; its local-model posture is smaller task scope, mandatory diff verification, and one bounded repair loop

- 2026-07-21: the `clojure-lib-revival` skill is renamed **`clojure-libs`** and broadened from "revive an abandoned lib" to the whole library lifecycle, adding an "Ongoing maintenance" section (dependency bump parity audits, dependency automation, release rules). It is the **canonical home for durable Clojure library process knowledge**, so all five agents share it rather than it living in Claude-only memory
- 2026-07-21: a dependency bump on a wrapper library is a **parity audit**, not just a green build: bump, audit the compare range for newly added surface, implement anything within the library's committed scope, and ship bump + features in one release. Audit **before** tagging, since Clojars is immutable. Beta/preview surface: wrap it when the library has already committed to that surface (e.g. anthropic-clj's beta agents platform), keeping it complete and marking it beta in docs; otherwise skip beta by default for a stable-focused wrapper. Deprecated surface is always skipped
- 2026-07-21: the split between the `clojure-libs` skill and the private memory dir is **process vs state**. Durable, non-sensitive process goes in the skill (public repo, all agents). Mutable or private state stays in the gitignored `extensions/memory/` (lib registry, roadmaps, credentials pointers, per-lib reference facts) because `ai-dotfiles` is a PUBLIC repo
- 2026-07-21: `setup.sh` now prunes dangling per-skill symlinks from the OpenCode/Codex/Gemini native skill dirs. The distribution loop only ever added, so renaming or removing a skill previously left a broken symlink in all three
- 2026-07-23: tmux transport is **no longer managed** by this repo. Removed `config/tmux.conf.tpl`, the `merge_managed_block ... "tmux AI transport"` call in `setup.sh`, its tests, and its docs/badge. Ghostty is now the sole managed terminal transport. Rationale: the settings were redundant with Ghostty's own capabilities for local use, and a managed tmux block has no per-agent format divergence to justify repo ownership. Users who still run tmux own their `~/.tmux.conf` directly. `setup.sh` has no un-merge, so the previously injected managed block must be stripped from live configs by hand (done for this machine)
- 2026-08-03: `~/.codex/config.toml` is **no longer managed** by this repo. Removed `config/codex.toml.tpl` and its `merge_managed_block` call in `setup.sh`, plus the README/AI.md/`configure-agents` references and the codex merge tests. Rationale: Codex rewrites that file itself and now persists `model`, `[features]`, `[tui]`, and `[[hooks.Stop]]` on its own, so the managed block re-declared tables Codex had already opened - TOML rejects a duplicate table and Codex hard-failed at startup with `duplicate key`. Appending a TOML fragment to a file another program rewrites is unsafe in principle (bare keys in the block also got absorbed into whatever table preceded them). Same rationale as the 2026-07-23 tmux removal. `setup.sh` has no un-merge, so the block must be deleted from live configs by hand (done for this machine; backup at `~/.codex/config.toml.bak-*`)
- 2026-08-03: `backup_if_needed` in `setup.sh` mirrors each target's path under `BACKUP_DIR` instead of flattening to basename. A flat dir keyed only on basename made the second `mv` of a same-named entry from a different agent root (e.g. `.codex/skills/foo` and `.agents/skills/foo`) fail with "Directory not empty" and abort the whole run before settings were rendered
- 2026-08-03: the durable decision log moved out of `instructions/AI.md` into `instructions/DECISIONS.md` (~1.2k est. tokens off every agent session). `/handoff` and `/catchup` resolve it conditionally - a `DECISIONS.md` beside the durable instructions file wins, otherwise the `## Decisions` section inside that file - so downstream repos with the old single-file layout keep working and no repo gets a `DECISIONS.md` created for it
- 2026-08-03: Claude Code drops `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` (set 2026-05-10 as a blanket precaution, no incident behind it). It suppresses the `tool-search-tool-2025-10-19` beta that defers MCP tool schemas, leaving ~36k est. tokens of schemas resident every session. There is no dedicated tool-search setting: `toolSearchEnabled` is computed from a remote gate plus per-model support. Claude-Code-only - OpenCode and Codex have no beta opt-out and no MCP schema deferral at all
- 2026-08-03: seven never-dispatched skills (`tdd`, `readme-badges`, `devserver`, `file-docs`, `mermaid`, `opencode`, `use-railway`) are `"off"` in `skillOverrides`, and `permissions.defaultMode` is `"auto"`. Both are Claude-Code-only keys, so the skills stay live for OpenCode/Codex/Gemini - an intentional divergence, since context budgets are per-agent
- 2026-08-10: `hf` (Hugging Face CLI) added to `instructions/AI.md`'s Tools table. Its `hf-cli` agent skill breaks the usual `extensions/skills/<name>/` model: `hf skills add` generates it live and writes real content straight to `~/.agents/skills/hf-cli`, not into this repo. `hf` sometimes auto-creates a symlink at `extensions/skills/hf-cli` pointing *into* `~/.agents/skills/hf-cli` - backwards from every other skill (source in-repo, symlinked out) - via its own project-detection heuristic. Verified this is not cwd-based: running `hf skills add` from `$HOME` and from `/tmp` both still produced the symlink inside `ai-dotfiles`, so a `cd` guard in `setup.sh` cannot prevent it. That symlink collides with `setup.sh`'s shadow-cleanup loop, which assumes anything at `~/.agents/skills/<name>` is a stray Gemini-precedence duplicate and `rm -rf`s it, destroying the real content Codex/Cursor/OpenCode read. Fix: `setup.sh` runs `hf skills add -g --claude --force` unconditionally, then `rm -f`s any `extensions/skills/hf-cli` symlink it produced, right after the call - cleaning up the side effect instead of trying to avoid it. Also noted but not fixed: Codex's own docs (learn.chatgpt.com/docs/build-skills) say it reads skills from `.agents/skills` (repo/user scopes), not `~/.codex/skills` as this repo's existing propagation assumes - unverified against a live Codex session, flagged for future investigation
- 2026-08-13: release workflows must extract the tag's section from the canonical changelog into `release-notes.md`, pass it with `body_path`, keep `generate_release_notes: true` for the compare link, and fail when the section is missing; `generate_release_notes` alone is empty in tag-and-push flows because GitHub builds it from merged pull requests, `environ` and `lein-shell` had tag triggers that never matched their pushed tags, and each repository must keep one changelog file so extraction cannot read a stale duplicate
- 2026-08-13: all 25 Clojure library repositories use one changelog heading format, `## [X.Y.Z] - YYYY-MM-DD`, one changelog filename, `CHANGELOG.md`, and one byte-identical release-notes extraction step. Uniformity was chosen over a fault-tolerant extractor: with one format the strict matcher becomes the enforcement mechanism, failing the release the moment a heading drifts, whereas a tolerant matcher would accept drift silently and let the formats diverge again. Rewriting the historical headings was judged safe because nothing deep-links a changelog heading anchor, and reformatting inherited upstream entries in the forks changes presentation, not facts. `environ` is multi-artifact and was restructured rather than excepted: each module now owns `environ/CHANGELOG.md` and `lein-environ/CHANGELOG.md` with the root file reduced to a pointer, so module identity lives in the path instead of the heading text, and its extractor reads the module directory named by the tag
- 2026-09-05: the `codex` and `agy` cross-agent **delegation skills are removed**, replaced by deterministic dispatch wrappers (`scripts/{agy,codex}-dispatch.sh`, symlinked onto PATH as `agy-dispatch`/`codex-dispatch`) plus thin Claude subagents (`extensions/agents/{codex,agy}.md`, renamed from `codex-runner`/`agy-runner`). Rationale: a haiku runner following the dense prose skill hallucinated a non-existent `agy exec` command (it is `agy --print`), the dispatch failed, and the runner then reviewed the code itself with its own Claude reasoning and reported it as a genuine Gemini cross-model review - twice, across sessions. The self-substitution prohibition was prose, and a cheap model's instinct to complete the task overrode it. The structural fix moves command-assembly and success-detection out of the model and into shell: the wrapper owns the invocation and encodes "did the run happen" as an exit code (agy: slug validated against `agy models`, silent no-op caught as empty-response-with-SUCCESS; codex: exit status captured directly with no trailing-command masking, real `thread.started` id required). A subagent can no longer invent a command or pass off a self-review, because a report with no wrapper-produced `conversation_id`/`thread_id` is `DISPATCH FAILED`. Delegation orchestration is now **Claude-only** (confirmed: orchestration always runs from Claude; OpenCode/Codex/agy are only ever targets), but the wrappers are plain shell on PATH so they remain callable by any agent. Wrappers take an injectable CLI (`$AGY_BIN`/`$CODEX_BIN`) unit-tested in `tests/dispatch.sh`; verified live against real agy 1.1.26 and codex 0.153.2. Supersedes the 2026-07-19 note that the `opencode` skill mirrors the `codex` delegation skill - only the `opencode` delegation skill remains.
